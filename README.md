# PING! — Secure P2P Messenger 🟢

**PING!** — лёгкий peer-to-peer (P2P) мессенджер на Python с графическим интерфейсом, локальной авторизацией и защищённым соединением между двумя устройствами.

## ✨ Возможности

- **P2P-соединение:** устройства соединяются напрямую по TCP.
- **E2EE-транспорт:** для каждой сессии создаётся новый эфемерный ECDH-ключ на `SECP384R1`.
- **Аутентификация ключей:** постоянный ключ устройства Ed25519 подписывает эфемерные ключи сессии.
- **Проверка личности:** при первом подключении показывается SHA-256 отпечаток ключа собеседника. Пользователь может вручную сравнить его с отпечатком на другом устройстве.
- **Запоминание доверия:** проверенный публичный ключ сохраняется в `trusted_peers.json`; изменение доверенного ключа приводит к отказу в соединении.
- **Защищённые сообщения:** после рукопожатия данные передаются через Fernet.
- **Текст, изображения и уведомления.**
- **Игра «Крестики-нолики».**

## 🔐 Модель безопасности

### Рукопожатие

Соединение использует два типа ключей:

1. **Эфемерный ECDH-ключ** — новый для каждого соединения. Он используется для получения общего секрета и обеспечивает forward secrecy на уровне сессионного ключа.
2. **Постоянный Ed25519-ключ устройства** — хранится локально и используется для подписи эфемерного ECDH-ключа.

После ECDH общий секрет передаётся через HKDF-SHA256, а результат используется как ключ Fernet.

> **Важно:** Fernet в библиотеке `cryptography` использует AES-128-CBC вместе с HMAC-SHA256. Поэтому называть текущую реализацию «AES-256 через Fernet» неправильно. В проекте используется 32-байтовый вывод HKDF, но это не означает, что Fernet работает в режиме AES-256.

### Отпечаток

Отпечаток — это SHA-256 от публичного Ed25519-ключа устройства, отображаемый группами по четыре шестнадцатеричных символа, например:

```text
A7F2:91C4:38B1:0D55:....
```

Сам публичный ключ не является секретом. **Приватный ключ устройства не передаётся по сети.**

При первом подключении рекомендуется сравнить отпечатки через другой доверенный канал — например, лично или по голосовой связи. После нажатия **«Доверять»** ключ сохраняется локально. Если при следующем подключении ключ изменится, соединение будет отклонено.

> Проверка отпечатка особенно важна при первом контакте: сама по себе подпись Ed25519 не предотвращает MITM, если атакующий смог подменить личность до того, как пользователь ей доверил.

- `cryptography`
- `plyer`

```bash
python -m pip install -r requirements.txt
```

Или вручную:

```bash
python -m pip install customtkinter cryptography plyer pillow
```

## ▶️ Запуск

```bash
python ping.py
```

При первом запуске приложение создаёт постоянный ключ устройства `identity_key.pem` и файл доверенных собеседников `trusted_peers.json`.

**Не публикуйте `identity_key.pem`: это приватный ключ устройства.**

## 🚀 Подключение

### Создание чата

1. Нажмите **«Создать чат»**.
2. Приложение найдёт свободный TCP-порт начиная с `55555`.
3. В чате будут показаны доступные IP-адреса и порт.
4. Передайте другу подходящий IP и порт.

### Подключение

1. Нажмите **«Подключиться»**.
2. Введите IP и порт устройства друга.
3. Дождитесь проверки безопасности.
4. При первом подключении сравните отображаемый отпечаток с отпечатком друга.
5. Нажмите **«✓ Доверять»**, только если отпечаток совпадает.

Для соединения через Интернет может потребоваться публичный IP и настройка проброса TCP-порта на роутере. В локальной сети обычно достаточно локального IP.

## 🧪 Тестирование

Проект использует стандартный `unittest`, поэтому отдельный тестовый фреймворк не требуется.

Запустить все тесты:

```bash
python run_tests.py
```

Или:

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют протокол фреймов, криптографическую сессию, Ed25519 identity, доверенные ключи, TCP-соединение и игровую логику.

## ⚠️ Ограничения текущей версии

- Первый контакт требует ручной проверки отпечатка для защиты от MITM.
- Приватный Ed25519-ключ сейчас хранится локально в файле без шифрования паролем ОС/приложения; доступ к файлу нужно защищать на уровне операционной системы.
- Fernet обеспечивает конфиденциальность и целостность сообщений, но текущий протокол не содержит отдельного счётчика сообщений для application-level replay detection.
- P2P-соединение не скрывает IP-адреса участников друг от друга и от сетевой инфраструктуры.
